5 Simplification and equality tests

5.1 Simplification functions

Let u, v be two elements of k (or of C, the Brown algebra, DD, L_0 or L, but not of LieEndo which is handled somewhat differently). Then u = v evaluates to true if and only if the internal representations of u and v coincide. In particular, if it evaluates to true, then u and v are certainly equal (in the mathematical sense, i.e. regarded as elements of a "free" mathematical structure). If for example u, v lie in C and u = v, this means that for any multiplicative conic alternative algebra \tilde{C} over any commutative ring \tilde{k}, the identity u = v holds whenever a1, a2, ... are replaced by arbitrary elements of \tilde{C} and t1, t2, ... are replaced by arbitrary elements of \tilde{k}.

However, it u = v evaluates to false, then this does not prove that u and v are not equal (in the mathematical sense). The following key function of this package aims to mitigate this problem.

5.1-1 Simplify
‣ Simplify( C, u )( operation )
‣ Simplify( u )( operation )

Returns an element of the parent structure of u (that is, of k, C, B, DD, L_0 or L) which is mathematically equivalent to u. Usually the internal representation of Simplify(u) is "easier"/"shorter"/"more canonical" than that of u. Thus to check whether u = v, one should check whether Simplify(u-v) equals zero. If this is true, then u and v represent the same element. If not, then they might still represent the same element, and we can try to prove this by hand by showing that Simplify(u-v) represents 0 (which is usually easier than showing that u-v represents 0). The function Simplify relies on several subroutines which can be studied in detail in gap/simplify.g.

If u is an element of a commutative base ring k, then the conic algebra C has to be supplied as well. For any other type of u, this is not necessary and the argument C will be ignored.

5.1-2 TestEquality for Lie algebra elements
‣ TestEquality( lie1, lie2[, print] )( operation )

Returns true if lie1, lie2 can be proven to represent the same elements using Simplify, and false otherwise. If the optional argument print is supplied and true, then in addition, simplifications of all non-zero components of lie1-lie2 in L_{-2}, \dots, L_2 are printed.

5.2 Testing equality of automorphism of L

For elements of LieEndo, equality tests with = are useless: Even GrpRootHomF4(F4Root, z) = GrpRootHomF4(F4Root, z) evaluates to false for technical reasons. Instead, the following functions should be used.

5.2-1 TestEquality of automorphism of a Lie algebra
‣ TestEquality( C, g, h[, n] )( operation )

Returns true if TestEquality(g(gen), h(gen)) is true for all gen in a certain list of Lie algebra generators of L. Otherwise returns the list of all lists [gen, Simplify(g(gen) - h(gen))] for any gen for which the test was not successful. The list of all generators gen on which we test equality is obtained by evaluating all root homomorphisms with image in L_{-2} + L_1 on 1_k (for long root homomorphisms) or on ConicAlgIndet(C, n) (for short root homomorphisms). The user should assure that ConicAlgIndet(C, n) does not occur in the definition of g and h, because otherwise the function may return incorrect positive results.

If n is not supplied, then ConicRank(C) is used as a default value.

5.2-2 TestEqualityPieces
‣ TestEqualityPieces( C, g, h )( operation )

Returns true in the same situations as TestEquality. Otherwise the output is a list of all non-zero "pieces" of all "error terms" Simplify(g(gen) - h(gen)) that arise during the test. By "pieces" we mean the underlying elements of k, C and DD that make up the error terms. Thus to prove that g and h are the same, it suffices to prove that all elements in the output list represent 0. As for TestEquality, the user should assure that ConicAlgIndet(C, ConicRank(C)) does not occur in the definition of g and h.
